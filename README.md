# X 一键分发

此目录是可直接加载的 Chrome MV3 插件产物，没有上游 TypeScript/Plasmo 工程或构建命令。

## X Article

- 已展开的文章：读取标题、完整正文和配图，记录文字与图片的排列顺序，保留段落、列表、emoji 和代码缩进。
- 文章卡片：在不切换当前页面的后台标签页加载全文，完成或失败后关闭该标签页。使用当前 Chrome 的 X 登录状态。
- 未读到全文时：面板提示打开文章重试或手动粘贴，阻止直接提交空正文或原始摘要。
- 文章详情页的独立阅读区域也提供分发按钮。普通推文和视频继续使用原有流程。

修改后在 `chrome://extensions` 重新加载「X 一键分发」，并刷新已打开的 X 页面。

## 同步到小红书长文写作

X Article 选择小红书分发时，自动进入“写长文 / 长文写作”→“新的创作”，填写标题、完整正文和所选配图，停留在编辑页。无配图也可同步；普通推文仍走原图文流程。

- 正文配图按原文位置插入，位于开头的封面作为开篇图片保留。面板取消选择的图片不会同步；同一图片多次出现时保留各处位置，但只下载一次。面板额外选入的图片追加在文末。
- 0.1.5 起配图问题只提示，不拦截后续同步：图片数量或位置不符时保留当前图片；单图准备、转换、上传失败或超时则提示，并继续填写正文和其他配图。完成后在编辑页保留配图提示，供手动补图或调整位置。
- 使用编辑器自身的图片粘贴上传流程，逐张等待小红书图片加载成功，再继续后面的文字；不会把 X 外链或临时预览图当作上传完成。0.1.4 修复只有文件的粘贴事件触发两次上传的问题，同一张图在原文的多处位置仍会分别保留。
- 正文和配图位置由同一次解析生成，避免含图列表、图片后的代码缩进或隐藏副本触发“正文不一致”。文字通过 TipTap 的文档事务写入并读取实际保存的数据校验，内联表情按文字处理，不计入配图。
- 不点击一键排版、下一步或发布；即使开启全局自动发布，小红书长文也会停在编辑页。
- 文章长标题不再受面板原先的 55 字限制；如果小红书编辑器自身设有限制，会提示调整，不静默截断。
- 标题使用独立输入框；正文移除抓取时附加在开头的同一文章标题，避免重复。
- 支持 PNG/JPEG，WebP 转成同尺寸 PNG 后上传。单张图片不得超过 10 MB，本插件一次准备的图片合计不超过 32 MB；超限图片会跳过并提示，其他内容继续同步。
- 多平台分发复用已下载的图片，失败的图片跳过，其他平台仍接收可用媒体的原数据结构。
- 如果配图定位信息缺失或与面板正文不一致，按面板当前正文填写，并将所选图片按原出现顺序放到文末，提示手动调整；标题可以独立修改。
- 未登录、已有其他草稿或标题/正文未完整写入仍会停止并保留现场；图片问题不阻止继续填写。重复执行已完成的同一次同步不会重复插图，图片状态后来发生变化时也只提示。

## 维护入口

- `article.js`：文章 DOM 识别、正文和图片提取、图文顺序、卡片全文加载；在原有 content script 之前加载。
- `static/background/service-worker.js`：加载原有后台脚本，并处理后台文章标签页的创建、提取和关闭。
- `static/background/rednote-longform.js`：长文填入函数通过 `chrome.scripting` 在页面 MAIN world 执行，读取 TipTap 暴露的 `view.dom.editor`。文字以文档事务写入，图片由站点上传，回读实际文档校验图文顺序；没有编辑器实例时才回退到 DOM/粘贴兼容路径。普通平台的脚本执行环境不变。
- `tabs/article-media.js`：在扩展页面下载所选配图、检查格式与大小、转换 WebP，准备图文顺序和可跨脚本传递的图片文件。
- `static/background/index.js`：现有分发函数接入长文适配器；`tabs/publish.4d5f7725.js` 透传 Article 信息、准备配图并复用媒体下载。
- `x.b4b04e83.js`：在原打包代码中接入提取器、文章入口、加载状态、提交校验和长文分发标记。包中的 `~extract/tweet` 模块是原提取器。
- `manifest.json`：上述两个入口的加载配置。

上游重新构建会覆盖产物里的接入改动；有源工程后，应迁移到原 `extract/tweet`、`DistributePanel` 和 background 模块。

图片粘贴必须同时提供空 HTML 段落作为有效的粘贴片段：小红书在 `onPaste` 内异步上传，未通过 `handlePaste` 返回已处理。只有文件、没有 HTML/文本时，ProseMirror 会进入 `capturePaste`，50 ms 后再次调用 `onPaste`，导致一张图上传两次。保留此修复和数量/位置检查，但图片检查只产生提示，不能再阻断正文。不要按 URL 去重，否则会丢掉原文有意重复的图片位置。

## 验证

后台消息、错误处理和临时标签页清理：

```sh
node --test tests/background.test.cjs
```

浏览器 DOM 和实际 React 面板回归（无需构建）：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
# 另一个终端
npx --yes agent-browser --session x-article-check open http://127.0.0.1:8765/tests/article.html
npx --yes agent-browser --session x-article-check eval 'window.articleTestResults'
npx --yes agent-browser --session x-article-check close
```

真实 MV3 扩展的消息与后台标签页集成测试：

```sh
node tests/extension.cjs
```

该测试需要 Playwright 和支持加载扩展的 Chromium。可用 `PLAYWRIGHT_MODULE` 指向已有 Playwright 模块、`CHROMIUM_PATH` 指向已有 Chromium 可执行文件。测试使用临时浏览器配置和模拟的 X 页面，不发布内容、不使用个人登录数据。真实 X 的页面可用性和登录状态仍需在用户浏览器中验证。

小红书长文写入与完整分发链路测试：

```sh
node tests/rednote-longform.cjs
```

除上述浏览器依赖外，此测试需要 `@tiptap/core`、`@tiptap/starter-kit` 和 `esbuild`，可用 `EDITOR_TEST_DEPS` 指向安装这些依赖的独立目录。测试使用真实 TipTap/ProseMirror 状态和模拟的小红书页面，验证长正文、图文位置、内联表情、图片文件上传、重复执行、草稿保护、登录/长度限制、WebP 转换和多平台媒体复用。图片使用与站点一致的 `onPaste` 异步回调和空段落清理，覆盖首次插图重复上传、慢速上传、同图相邻出现及 DOM 兼容路径。图片错位、数量异常、素材缺失、定位过期、部分/全部下载或上传失败时，断言正文完整、后续配图继续、提示保留且不自动发布；真正的正文写入失败仍报告错误。另运行真实 MV3 扩展的 X 面板→分发窗口→MAIN world 写入链路；图片上传服务器为模拟服务，实际账号的编辑页与上传仍需登录验证。
